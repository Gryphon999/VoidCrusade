# GRAPHICS_AAA_TASK.md — Premium, AAA-quality visuals

Branch for this work: **`claude/graphics-aaa`** (created from the current state; PR #1 must stay untouched by this work).
Read first: `README.md`, `GRAPHICS_TASK.md`, `CONTENT_TASK.md`, `docs/`, then the renderer code in `src/scenes/BattleScene.ts`, `src/assets/*`,
`src/systems/CameraSystem.ts`, `src/effects/*`, `src/ui/*`.

The owner's verdict after the last round: much better, but still not premium. The target now is a game that looks **expensive and professional**,
in the league of modern RTS titles (Dawn of War III / Company of Heroes 3 / StarCraft II / Warhammer 40,000: Battlesector for the mood, cinematic UI and polish).
Be honest about physics: a solo project without a studio art team cannot literally match AAA content volume. What we CAN match is *art direction, lighting,
material quality, animation feel, effects, post-processing, UI polish and coherence*. Aim for that, and critique your own output harshly.

## 0. Rules
- Work on branch `claude/graphics-aaa`. Push after every phase. Do not open a PR until the end (then ONE PR into `main` that includes everything up to date; if PR #1 is still open, base on it and say so).
- Gameplay rules, balance, AI, tutorial logic and localisation must not regress. Simulation must stay independent of rendering (see A1).
- Bundle/runtime budgets (Yandex Games target): total zip ≤ ~30 MB; first load to main menu ≤ ~15 s on a mid laptop with a progress bar; ≥ 45 FPS at 1080p on integrated graphics
  (AMD Radeon 860M class) on **Medium**, 60 FPS on High for a normal GPU. Provide quality tiers **Low / Medium / High / Ultra**, a resolution-scale slider, and an FPS counter toggle. Adaptive quality drop if FPS stays low.
- Art is still generated by code (no hand-made external art files, no downloaded assets). Allowed: runtime generation **and** build-time generation scripts that bake textures/sprite atlases/normal maps into compressed files
  (WebP/PNG/KTX), as long as the files are produced by scripts in `scripts/` and reproducible. Keep the total size within budget.
- Native rendering resolution: no upscaled 1280×720 image at 1080p/1440p/4K. Support `devicePixelRatio`, crisp UI and sprites at any resolution.
- Every phase ends with before/after screenshots (few, compressed, in `docs/screens/aaa/`) and a short self-critique in the commit message or `docs/graphics-log.md`: what is still weak, what will be done next.

## 1. Reference targets (what "premium" means here)
1. **Coherent art direction**: one palette, one lighting logic, one material language. Desaturated grimdark base, controlled saturated accents (faction colors, energy, fire, blood), strong warm/cold contrast.
2. **Materials**: metal (scratched, painted, worn edges, rust, oil streaks), stone, chitin/bone/biomass, cloth/leather. Visible specular highlights, emissive parts, ambient occlusion in crevices, edge wear.
3. **Lighting**: a clear key light with real shadows from every unit/building/prop, soft ambient, rim lights on units, local light pools from fire/energy, light shafts/atmospheric fog, day/dusk/night variants per map.
4. **Detail density**: terrain with height variation and layered materials, decals (scorch, blood, tracks, cracks), props and clutter, ruined architecture, vegetation-like growth (null-horde biomass, dead trees), ground-level fog and drifting ash.
5. **Animation feel**: weight and anticipation, secondary motion (cloth/banners/cables/tentacles), synchronized squad behaviour, hit reactions, ragdoll-lite deaths, vehicle suspension and turret recoil.
6. **VFX**: layered explosions (flash, fireball, smoke, debris, shockwave, heat distortion), volumetric-looking smoke, energy weapons with glow and bloom, muzzle flashes with light, tracers, sparks, blood mist, screen-space effects.
7. **Post-processing**: bloom, color grading (LUT), subtle vignette, tilt-shift depth of field for the battlefield, chromatic aberration on impacts, film grain, ambient occlusion approximation, sharpen. Toggle per quality tier.
8. **UI**: cinematic, consistent, crisp at any DPI. Ornate but readable, animated transitions, tasteful sounds, 3D-rendered unit/building portraits, smooth minimap, high-quality iconography, typography with proper hierarchy.
9. **Camera and cinematics**: smooth inertia, subtle shake on explosions, battle-start fly-in, victory/defeat shots, campaign-map transitions.

## 2. Phases

### A0 — Rendering technology spike (must be done first, time-boxed)
The current renderer is Phaser 2D with a squashed oblique view. It is the main ceiling for quality. Build **small comparable prototypes** of the same scene
(one Iron Void squad, one building, terrain patch with a cliff, an explosion, 3 lights, shadows) and measure quality + FPS + bundle size + effort:
1. **Phaser 2D + Light2D + normal maps**, sprites baked from procedural 3D models at build time (8 facings, several animation frames, normal + emissive maps).
2. **Full 3D (Three.js or Babylon.js)** for the battlefield: procedural low/mid-poly models, PBR materials with generated textures, real shadow maps, instancing for squads, post-processing pipeline, orthographic-ish tilted perspective camera.
   Phaser can remain only for menus/HUD, or HUD becomes DOM/canvas overlay.
3. **Hybrid**: 3D renderer for terrain/units/buildings, existing simulation and HUD kept.
Write `docs/graphics-decision.md` with screenshots, FPS numbers on this machine (report which GPU/CPU), bundle sizes, risks, and a recommendation. **Bias**: if the 3D prototype reaches the FPS budget with 100 units, choose 3D — Dawn of War itself is a 3D game and this is the only route to real shadows, PBR and camera freedom.
If you choose full 3D, the simulation (units, combat, AI, pathfinding, fog) must keep working unchanged behind a renderer interface (A1). If none of the options reaches the FPS budget, choose option 1 and document why.
Do not spend more than a small share of the total effort here, but do not skip it; the decision drives everything else.

### A1 — Renderer architecture
- Separate **simulation** from **rendering** (data in, draw calls out). Define a `Renderer` interface and move all drawing behind it so the chosen approach can be swapped and tested. Keep input mapping (screen ↔ world) in one place.
- Asset pipeline: `scripts/bake-*.ts` for models → sprites/atlases or model data, textures, normal maps, LUTs; reproducible with `npm run bake`; outputs go to `public/` (or generated at load if fast enough). Document in README.
- Quality settings infrastructure (tiers, resolution scale, adaptive quality, FPS overlay), GPU capability detection with graceful fallbacks (WebGL2 → WebGL1 → Low path).

### A2 — Terrain and environment
- Height-varied terrain (real height if 3D; faked with parallax/extrusion if 2D) with layered materials (ash, cracked earth, scorched rock, metal plating, biomass), splat-map blending with noise, per-material normal/roughness, macro color variation, detail textures so it never looks tiled.
- Cliffs and rock formations with proper faces and edge highlights; ruins with gothic architecture (arches, buttresses, statues, broken walls); roads; craters; lava/acid pools with emissive glow and animated surface; ash drift, ground fog, embers, dust; distant background (mountains/planet/sky) instead of black void.
- Prop library with variants: rocks, wrecks, bones, banners, spikes, pipes, crates, fires, dead trees, biomass growths. Scattering rules and clustering so maps feel authored.
- 3 maps get distinct atmospheres (color grade, fog, light direction/time of day).

### A3 — Units and characters
- New model quality: each infantry squad member made of many detailed parts (helmet, visor, pauldrons, armor plates, backpack, weapon, cloth, cables, banner), with wear/dirt, emissive lenses, faction insignia, rim-light readability from the tilted camera. Heroes and vehicles clearly bigger and more detailed.
- Null Horde: chitin plates, glistening wet look (specular), bone spikes, translucent membranes, glowing eyes/veins, asymmetry.
- Animations: idle variety, walk/run with weight, aim/fire with recoil and muzzle light, reload, hit reaction, death variants (fall, slump, explode, dissolve for aliens), melee swings; vehicles with suspension, turret tracking, track/wheel motion, exhaust; smooth blending between states.
- Formation and crowd polish: individual offsets, spacing, no jitter, no overlapping, squad members face targets.
- Shadows under everything; ambient occlusion contact shadows.
- Portraits for HUD rendered from the actual models (A7).

### A4 — Buildings
- Kitbash-quality structures (bastions, conduits, barracks, foundries, bunkers, sensor arrays, shield projectors, batteries, walls/gates, biomass nests, spires, maws, vats) with layered volumes, greebles, trims, lights, vents, banners, glowing cores, smoke stacks, animated parts (rotating radar, pulsing organic sacs).
- Construction sequence: scaffolding, cranes/drones or growth animation for the Horde, welding sparks, dust; damage states (cracks, fires, missing chunks) at 75/50/25% HP; spectacular destruction with debris and lingering ruins.
- Capture points, relics, listening posts, beacons with distinctive silhouettes and effects.

### A5 — Lighting, shadows, atmosphere
- Single strong directional key light with shadows (soft edges), fill/ambient, rim light; time-of-day per map.
- Dynamic point lights from fire, muzzle flashes, explosions, energy cores, capture points (limit count, fade by distance, respect quality tier).
- Ambient occlusion (SSAO or baked contact shadows), fog of war restyle (volumetric-looking, smooth edges, explored-vs-visible states), atmospheric perspective, god rays/light shafts on High, heat haze near fire and engines.
- Color grading (LUT per map), vignette, filmic tone mapping; keep whites from clipping; blood and energy colors must stay punchy.

### A6 — VFX
- Particle systems with pooling and atlases (flipbook smoke/fire/explosion), additive/normal blends, soft particles, light emission; stylised but rich. Budget per tier.
- Weapons: distinct visual identity per weapon (bolt tracer, autocannon spray, flamethrower stream, artillery arc with trail, acid globs, plasma, missiles with smoke trail), impact effects per surface (metal sparks, dirt puffs, flesh mist, acid sizzle).
- Explosions with shockwave, debris, scorch decals, screen shake (setting), heat distortion; blood system upgraded (mist, splats, pools, footprints in blood, alien ichor).
- Ability effects (grenades, smoke, shield bubble with fresnel edge, barrage markers, drop-pod entry trails, psychic waves) polished and readable.
- Decal system (cap and fade) for scorch, blood, tracks, craters.

### A7 — HUD, menus, campaign map, cinematics
- Redesign HUD to feel like a premium RTS: beveled metal/ornate frames with real material detail (not flat), animated glow on active elements, smooth transitions, hover/press feedback with audio, crisp icons (redrawn consistently, with faction variants), portrait windows rendered from the 3D/sprite models with idle animation, squad rosters with health/morale/veterancy, command grid with cooldown sweeps.
- Typography: consistent font stack that supports Cyrillic well; hierarchy, letter-spacing, drop shadows for readability; scalable UI (UI scale slider).
- Main menu with a live 3D/parallax scene (planet, fleet, drifting embers), animated logo, tasteful music sync. Loading screen with lore tips and art.
- Campaign map: rendered planet with atmosphere, cloud layer, city lights/fires, animated territory borders and fleets, battle markers, transitions into battle (fly-in).
- Battle start fly-in, victory/defeat cinematic camera moves and banners, mission briefing screens with stylised art.
- Tutorial overlay and Encyclopedia restyled to match; Encyclopedia previews use the real high-quality models.

### A8 — Camera, feel, polish
- Camera inertia and smoothing, edge scroll polish, zoom with tilt adjustment (closer = lower angle), optional rotate, focus-on-event, subtle shake on big explosions (toggle), minimap ping.
- Selection and command feedback: elegant rings/brackets, waypoint lines, move/attack pulses, target highlights, damage numbers optional.
- Audio hooks matched to new visuals (impact sounds sync, ambience per map) — small tuning only.

### A9 — Performance and quality tiers
- Profile at 100+ units, 60+ buildings, heavy effects. Instancing, batching, atlases, culling, LOD (model/shader/particle), object pooling, shader complexity control, avoid per-frame allocations, texture compression where sensible.
- Verify tiers: Low (no post-fx, simple shadows), Medium (default), High, Ultra. Record FPS numbers per tier in `docs/performance.md` (state hardware).
- Loading time optimisation: lazy bake, progressive loading, caching in IndexedDB (try/catch).

### A10 — QA, comparison, honesty report
- Screenshot script covering menu, campaign map, each map at battle start, big fight, each faction's roster line-up, buildings line-up, HUD at 1280×720 / 1920×1080 / 2560×1440, in RU and EN; compressed (WebP/JPEG), few files.
- `docs/graphics-log.md`: per-phase before/after, remaining weaknesses versus the reference games, and a ranked list of what would improve quality most next.
- Update `README.md`: graphics settings, new commands (`npm run bake`), requirements (WebGL2), troubleshooting.
- Final PR description: summary per phase, screenshots, performance table, known limitations. Confirm tutorial, campaign, skirmish, RU/EN, voice-over and all C-phase features still work.

## 3. Definition of done
- Side by side with the current version, the new one looks like a different, much more expensive game: real lighting and shadows, rich materials, believable animation, cinematic HUD.
- All quality tiers run within budget; game boots on WebGL2 hardware and degrades gracefully.
- No gameplay/AI/localisation regressions; `npm run build` passes; the branch is reproducible from scratch (`npm install && npm run bake && npm run build`).
